Imports the accounting data of a
`Papierkram <https://www.papierkram.de>`__ account into Odoo: contacts,
customer invoices, cancellations and credit notes, expense and income
vouchers, payments, fixed assets with their depreciation, and the
original PDF documents.

Every payment is posted as a cash entry with its own payment date on a
dedicated money account. A cash-basis profit computation (German
*Einnahmenüberschuss­rechnung*, see ``l10n_de_euer``) can therefore tell
exactly when money came in or went out. Imported documents keep their
Papierkram number, and an import can be run again without creating
duplicates.

.. IMPORTANT::
   This is an alpha version, the data model and design can change at any time without warning.
   Only for development or testing purpose, do not use in production.
   `More details on development status <https://odoo-community.org/page/development-status>`_

Use Cases / Context
===================

Papierkram exports one ZIP file per year, cut by the *creation date* of
each document. A payment therefore appears in the export of the year its
document was created, which is often not the year it was paid. The
module merges all yearly exports before importing.

Some payments are not listed in Papierkram's payment table because they
were matched with a bank transaction. The module derives them from the
invoice's last payment date or the voucher's payment date and lists them
separately in the log.

This module helps with migrating bookkeeping data. It does not replace
the review by the taxpayer or a tax advisor; check the log and the
imported figures before relying on them.

Configuration
=============

The company must use the German chart of accounts SKR03 or SKR04
(``l10n_de``).

The import creates four journals unless you select existing ones:
*Papierkram Invoices*, *Papierkram Vouchers*, *Papierkram Depreciation*
and *Papierkram Payments*. Payments of the payment journal are posted
directly on its money account so that each payment is a cash entry with
its date.

Do not set a lock date before importing: Odoo moves entries of a locked
period behind the lock date, which would change payment dates.

Usage
=====

1. In Papierkram, open *Einstellungen → Export und Import* and create
   one export *Vollständig (CSV, PDF)* for every year, including the
   first one.
2. Optional but recommended:

   - *Ausgaben → Anlagegüter*, filter *Alle*, button *CSV*: the fixed
     assets.
   - The category list with SKR03 accounts (CSV with the columns
     ``name``, ``skr03``, ``abschreibungsart``, ``typ``). Without it,
     vouchers can only be imported if all their categories are known.
   - For vouchers with several categories, a split file with the columns
     ``belegnummer;position;kategorie;betrag_brutto``; Papierkram's
     export does not contain the amount per category.

3. In Odoo, go to *Invoicing → Configuration → Papierkram Import*,
   create an import and upload the files.
4. Choose the *Scope*: the complete history, or only the open items
   (unpaid invoices and vouchers with their partial payments). A later
   import with the complete history adds the rest; documents already
   imported are skipped, also by a new import of the same company.
5. Click *Check* and read the log. Blocking issues must be solved first.
6. Click *Import*.

A document imported once is not updated by a later import: a payment
that Papierkram records afterwards for an imported invoice has to be
entered in Odoo.

With the cash-basis profit computation ``l10n_de_euer``, the module
``l10n_de_papierkram_import_euer`` (installed automatically) also takes
the fixed assets over into its asset register; for an import made
before, the button *Take Over Fixed Assets (EÜR)* does it later. With
``sale_timesheet``, the module ``l10n_de_papierkram_import_timesheet``
(installed automatically) imports products, time entries and the
unbilled work.

Known issues / Roadmap
======================

- Read the category list and the voucher splits directly from Papierkram
  instead of separate files.
- Import line items of invoices (Papierkram's CSV only contains totals;
  the PDF is attached).
- Import bank transactions as bank statement lines.
- Regular VAT: vouchers with several lines and different tax rates.
